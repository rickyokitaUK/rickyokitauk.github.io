Why I keep building

Games came first.

I started making games because I wanted to turn imagined worlds into something people could experience.

Software engineering became my career, but that instinct never disappeared.

Now I’m bringing those worlds together: the engineering discipline I’ve built over the years and the creative freedom that drew me to games. AI is one way I’m exploring how smaller teams can build more ambitious experiences.

Keep learning. Keep building. Keep ideas playable.

AI-assisted production

Building the pipeline

AI can generate ideas and assets quickly. The harder problem is turning those outputs into reliable, editable and performant game content.

I’m experimenting with AI agents, Unity automation, validation and simulation to make that production layer more dependable.

  1. 01 Idea / reference
  2. 02 Concept / asset generation
  3. 03 3D / rigging / animation
  4. 04 Unity integration
  5. 05 AI agent / MCP
  6. 06 Validation
  7. 07 Automated testing
  8. 08 Playable build

The goal isn’t to automate creativity away. It’s to shorten the distance between an idea and a working game while keeping engineering discipline, performance and creative control.

About

Software engineer and game developer — based in Liverpool, with roots in Hong Kong.

Games came first: experiments as a teenager, then educational titles in C++ and DirectX. After that came more than a decade of commercial software across web, enterprise, fintech and public services.

Now those paths are coming back together, with that engineering foundation applied to gameplay systems, simulation and AI-assisted game production.

How can small teams use AI and better tools to build ambitious games without sacrificing reliability, performance or creative control?
